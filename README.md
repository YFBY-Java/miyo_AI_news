# miyo_AI_news

本地米游资讯视频工作台。将资料导入、分镜卡片、手动配图、口播、声线、时间轴、四游戏风格、预览和 MP4 导出放在同一项目中管理。

本工程从原机器上的 `miyo-news-card` 基线 `a11a118` 复制渲染实现、字体和历史样例，拥有独立源文件、依赖目录和数据目录；运行时不读取或写入原工程。声线参考素材已放入本项目的 `voice-library/`，与源码一同提交和迁移；MLX 推理环境、模型和系统工具仍需在目标机器准备。

## macOS 与 Windows 支持

网页、项目编辑、归档配音复用、预览和视频导出使用同一套源码与配置。macOS 和 Windows 均需 Node.js 20 以上；配音控制器需 Python 3.10 以上，推荐使用 CI 对应的 Python 3.11。

| 能力 | Windows / Intel Mac | Apple Silicon Mac |
| --- | --- | --- |
| 编辑、配图、预览与 MP4 导出 | 支持，导出需 Chromium、FFmpeg/FFprobe | 支持，工具要求相同 |
| 复用匹配的历史琪亚娜口播 | 支持，需 Python 与 FFmpeg/FFprobe | 支持 |
| 新晓晓口播 | 支持，需 `edge-tts` 和网络 | 支持，要求相同 |
| 新琪亚娜口播 | 当前 MLX 路径不可用，会明确报错 | 需独立 MLX 环境、完整模型及项目参考素材 |

选择琪亚娜不会在失败时自动替换为晓晓；Windows 或 Intel Mac 制作新口播时，可手动选择晓晓。跨平台回归通过仓库的 macOS/Windows CI 执行，具体实测结果见 [验收记录](docs/VERIFICATION.md)。

## 打开工作台

使用一个无版本号的项目根目录 `miyo_AI_news/`，工程和声线参考素材都在其中：

```text
miyo_AI_news/
├── app/、src/、scripts/、tests/  应用源码与测试
├── public/、fixtures/           字体与历史示例
├── voice-library/              声线参考素材，纳入 Git
├── docs/distribution/           原始交付说明和文件清单
├── package.json、package-lock.json
└── data/                       本地制作数据，独立备份
```

在 macOS 终端或 Windows PowerShell 中，从 GitHub 克隆并安装锁定版本的依赖：

```sh
git clone https://github.com/YFBY-Java/miyo_AI_news.git
cd miyo_AI_news
npm ci
npm run dev
```

浏览器访问 [http://127.0.0.1:3002](http://127.0.0.1:3002)。只监听本机地址。导出视频还需 FFmpeg/FFprobe，并执行 `npx playwright install chromium` 安装匹配项目版本的浏览器。声线参考素材随仓库恢复，模型和推理环境按 [运行与维护](docs/OPERATIONS.md) 准备。

从 `.env.example` 复制一份 `.env.local` 保存本机配置；macOS 可用 `cp .env.example .env.local`，PowerShell 可用 `Copy-Item .env.example .env.local`。网页、CLI、worker 和 Python 统一读取项目 `.env.local`、`.env`，外部环境变量优先。`MOYO_*` 的资源相对路径按项目根解析，例如 `MOYO_DATA_DIR=./data`；配置可随整个目录移动。仅在确实使用自定义声线资源时填写对应覆盖项，否则会禁用历史声线 seed 复用。

首次打开会导入一份星铁历史样片，日期为 **2026-09-28 至 2026-10-02**。其约 4 分 17 秒配音与精确时间轴已保存在本工程中；这是历史示例，不是实时新闻。

## 一期视频的制作流程

1. **新建或复制项目**：选择原神、崩坏3、星穹铁道、绝区零的视觉风格。
2. **导入资料**：读取公开网页，或直接粘贴文字。保存网页提取文本或手工粘贴内容、来源链接及核对状态；发布日期与发布方需人工核对补全。网页需要登录或动态加载时，使用粘贴方式。
3. **整理并编辑分镜**：资料按段落整理成可编辑草稿。分别修改口播和卡片正文；增删、排序分镜或卡片，关联来源。草稿整理采用规则切分，不声称自动理解或核实新闻。
4. **手动配图**：选中一张卡片，在右侧配图区域上传或拖入本机图片，也可复用素材库图片。选择左图右文、右图左文或背景图，调整完整显示/裁切填满及画面位置；保存后应用到预览。
5. **选择配音**：默认「琪亚娜-稳重轻角色感-v2-轻角色-基准」、1.1 倍速；也可选晓晓普通话。先试听当前分镜，再合成整期。
6. **调整画面**：在每张卡片的「中间卡片尺寸」中调节宽度和高度，预览即时更新，保存后用于导出。还可选择粒子密度、字幕字号、章节幕切，以及每次聚焦的卡片和转场。聚焦时间以本段配音的百分比保存。
7. **同步预览**：已合成时，以音频播放时间驱动画面与字幕；未合成时明确显示估算时长，支持无声预览。拖动底部时间轴可以定位。
8. **导出**：后台串行执行配音、时间轴、逐帧渲染、音画合成和媒体检查；每次输出保留独立版本。支持取消、失败原因和按当前内容重试。

修改画面正文、风格或粒子时可以复用已合成音轨；修改口播、语速或声线会让整期配音计划失效。新合成按场景复用原速缓存，修改语速不会在已变速音轨上二次加速。

## 手动配图

每张卡片可以配一张图片，图片会跟随该卡片参与聚焦和转场，四种游戏风格都支持。未配图的卡片继续使用原有纯文字样式。背景图带文字遮罩，左右分栏将图片与正文分开；超长正文仍建议拆成多张卡片。

- 支持静态 PNG、JPG/JPEG、WebP，单张最多 12 MB、3200 万像素；一期所引用的不同图片合计最多 60 MB。
- 上传保存原始字节和文件名；裁切、位置及背景遮罩仅影响呈现，不覆盖原图。动态 GIF、APNG、WebP 暂不支持。
- 调整图片或移除卡片配图不需要重新合成配音。替换图片会生成独立素材，已导出视频和历史 HTML 保持原样。
- 移除配图只解除当前卡片的引用，素材库中仍可复用；本版没有永久删除素材功能。
- 导出 HTML 内嵌所用图片，不依赖本地服务器或原图片路径；导出前检查图片完整性和解码状态。原图仍需随 `data/assets/` 一起备份。

## 四游戏风格

画面已去掉信息来源行、分镜副标题，以及底部资料日期和时间文字；这些原始资料仍保存在项目中。主标题、字幕、章节导航和进度线继续显示，腾出的空间用于更大的中间卡片。

每张卡片可独立设置 **800–1720 px 宽、360–660 px 高**，基于 1920×1080 画布。可拖动滑杆或输入整数，点击「恢复默认」回到各卡片略有差异的默认尺寸（首卡约 1440×620）。改变大小会实时预览且保持播放位置；保存后重新打开与视频导出使用同一尺寸，不需要重新合成配音。较小卡片遇到长正文仍应拆卡，避免文字过密。

| 风格 | 画面与动效 |
| --- | --- |
| 原神 | 米白纸张、青绿自然色、叶片与风线、旅行手记和风卷章节幕切 |
| 崩坏3 | 午夜蓝、香槟金、女武神档案、星云碎光与星幕 |
| 星穹铁道 | 深蓝车票、星线、青色光边，保留金色斜向车票横扫及四种卡片切换 |
| 绝区零 | 黑白与安全黄、切角拼贴、录像频道、信号颗粒与频道切换 |

四种风格都通过同一个完整视频渲染入口工作。原版星铁效果作为迁移基准，其余三种的长视频外观是在新工程内扩展的。切换风格改变呈现方式，不会把星铁新闻自动改写成其他游戏新闻。

## 文件保存位置

```text
data/
├── projects/<id>.json          每期可编辑项目，带 revision
├── assets/<id>/                手动上传的原图与尺寸、原名、哈希等元数据
├── jobs/<id>.json              任务进度和状态
├── runs/<job-id>/
│   ├── project.json           本次生成的不可变内容快照
│   ├── narration.wav / .m4a   配音（复用任务可能仅有 WAV）
│   ├── voice-plan.json        实际音频时长和场内字幕
│   ├── episode.json / .html   编译后的统一时间轴与画面
│   ├── subtitles.srt          字幕
│   ├── video.mp4              校验完成后发布的成片
│   ├── render-report.json     画面、音画参数与完整解码结果
│   └── *.log                 当前任务日志
├── cache/voice/               按实际输入指纹保存的原速配音缓存
└── verification/              本次真实联调、声线和浏览器证据
```

`data/`、`node_modules/`、`.next/`、`.next-build/`、`backups/` 和真实 `.env` 配置不纳入 Git。备份用户制作内容时需要同时保存 `data/`。`fixtures/starrail-weekly/` 包含可再导入的历史原速/最终配音与编辑稿，约 50MB；保留它们可在没有 TTS 模型时恢复已有示例。

成片不会写回原项目。最终检查通过前只产生 `video.partial.mp4`，不会被列为成功视频。

## Git 提交范围

以 `miyo_AI_news/` 作为独立 Git 仓库根目录。提交范围包括源码、测试、配置模板、锁文件、字体、历史示例、文档和 `voice-library/`；声线目录仅有参考音频、参考文本和参数 3 个文件，约 1.1 MB。克隆同一个仓库即可得到这些项目资源，无需另建同级声线目录。

在项目根目录检查并提交自己的修改：

```sh
git status --short
git add .
git diff --cached --stat
git commit -m "Update project"
git push origin main
```

`data/` 中的编辑项目、用户图片、缓存和成片仍需单独备份；本机模型与推理环境不会随 Git 恢复。

## CLI 与生产构建

网页和 CLI 复用同一后台任务流程：

```sh
npm run render
npm run render -- starrail-demo prepare
npm run render -- starrail-demo render
```

不带项目 ID 时列出项目。正常情况下网页会自动启动后台进程，不需要手动启动 worker。也可以运行 `npm run worker` 处理已排队任务。

```sh
npm run build
npm start
```

开发服务运行期间，可在 `.env.local` 配置 `MOYO_NEXT_DIST_DIR=.next-build`，然后运行 `npm run build` 在独立构建目录校验。生产启动也需使用相同配置；详情见 [运行与维护](docs/OPERATIONS.md)。

## 配音与本机工具

完整参数、环境覆盖、缓存和执行记录见 [VOICE.md](docs/VOICE.md)。新琪亚娜口播使用 Apple Silicon Mac 上的 MLX-Audio / Qwen3-TTS 模型；晓晓使用 `edge-tts` 并需要网络。默认模型目录为项目 `models/Qwen3-TTS-12Hz-1.7B-Base-4bit/`，MLX 环境为 `.venv-mlx/`。缺少声线资源时明确报错，不会自动换声线或下载模型。

字幕采用语义短句与附近静音估算；历史配音复用保存的时码。尚未接入 ASR 强制对齐。UI 可以调整卡片聚焦点，字幕本身暂没有逐条手工时码编辑器。

## 验证

```sh
npm run typecheck
npm test
npm run test:python
npm run check:runtime
npm run build
```

测试覆盖项目校验、稳定卡片 ID、配音失效规则、时间轴编译、媒体 Range 与路径边界、四风格渲染/消息桥、TTS 缓存与真实音频处理。`check:runtime` 使用隔离工程和归档音轨执行实际配音准备、短片导出、取消与复用，需要 Python、FFmpeg/FFprobe、Chromium；不调用在线 TTS 或新 MLX 推理。集成验收与具体输出见 [验收记录](docs/VERIFICATION.md)。

Windows 文件符号链接测试在缺少 Developer Mode 或相应权限时，会逐项报告明确的 `SKIP`；目录逃逸继续用 junction 实际验证，其他测试照常执行。浏览器缺失或渲染失败会令测试失败。CI 在 macOS 与 Windows 安装真实 Chromium 后执行完整检查，原 Mac 交付验收单独保留为历史证据。

## 当前适用范围

- 单机单用户，生成任务串行处理；刷新页面不终止后台任务。
- 固定 1920×1080 / 24fps / H.264 + AAC，单期最多 40 分镜、每分镜 1–6 卡，最长 30 分钟。
- 支持资料链接读取与手工导入；没有全网自动搜索、自动发布或多人协作。
- 资料切分草稿需要人工编辑和事实核对；不会根据游戏主题编造新闻。
- 预览和导出共享同一个 `seek(seconds)` 画面实现。完整导出包含卡片正文布局溢出检查，超长正文应拆卡或缩短后重试；标题与字幕仍需视觉检查。
- 失败可以复用已完成且校验有效的音频；视频暂从头重渲染，不提供逐帧断点续渲染。

架构与接口说明见 [ARCHITECTURE.md](docs/ARCHITECTURE.md)。
